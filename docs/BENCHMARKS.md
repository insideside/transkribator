## Условия

Компьютер: MacBook Pro на Apple M4 Pro (14 ядер CPU, из них 10 производительных и 4 энергоэффективных, 20 ядер GPU),
48 ГБ общей памяти, macOS 26. Замеры сделаны 24-25 сентября 2026 года. Версии: Python 3.12, mlx-whisper 0.4.3,
faster-whisper 1.2.1, sherpa-onnx 1.13.8.

Тестовые записи синтетические и в репозиторий не входят:

| Запись | Описание |
|---|---|
| Диалог 70 с | 11 реплик трёх голосов: мужской и женский голоса Microsoft Edge TTS и голос macOS «Милена». Добавлен розовый шум, формат AAC 64 кбит/с, 48 кГц, моно, как у диктофона iPhone |
| 5, 7 и 20 мин | тот же диалог, повторённый подряд. В 20 минутах 17 повторов и 187 эталонных реплик |
| 63 мин | 51 повтор диалога с паузами от 0 до 8 секунд и двумя минутами тишины посередине, AAC 64 кбит/с, 561 реплика |
| Тишина и ALAC | фраза, 40 секунд тишины с шумом, ещё фраза. Формат ALAC, как в режиме «без потерь» у диктофона |
| Реальная запись | круглый стол на 50 минут, несколько участников, шум зала. Содержимое не публикуется |

Как считалось:
- WER, доля ошибок в словах относительно эталонного текста. Перед сравнением убираются пунктуация и регистр,
  «ё» считается за «е». Часть ошибок на самом деле ошибками не является: Whisper пишет «12%» вместо
  «двенадцать процентов».
- «Реплики верно» показывает, у скольких эталонных реплик правильно определён говорящий. Говорящим реплики
  считается тот, кому принадлежит большая часть её времени, номера говорящих сопоставляются наилучшим образом.

## 1. Точность распознавания

| Модель | Движок | Запись | WER | Время |
|---|---|---|---|---|
| large-v3 | MLX (GPU) | диалог 70 с | 2,4 % | 17-20 с вместе с загрузкой модели |
| large-v3-turbo | MLX (GPU) | диалог 70 с | 4,0 % | 13,5 с |
| large-v3-turbo | faster-whisper, CPU int8 | диалог 70 с | 4,0 % | 16 с |
| large-v3 | MLX (GPU) | 63 мин | 2,46 % | 8,6 мин |

На 40 секундах тишины Whisper ничего не выдумал. Фразы вроде «Субтитры сделал...» на всякий случай ещё и
отсекаются фильтром. Известное ограничение: Whisper изредка пропускает слово на стыке своих 30-секундных окон,
примерно 4 слова на час записи (0,06 %).

## 2. Разделение по голосам

### Выбор модели голосовых отпечатков (диалог 70 с, sherpa-onnx)

| Модель | Авто, порог 0,5 | Авто, порог 0,6 |
|---|---|---|
| 3D-Speaker ERes2NetV2 (выбрана) | 11/11 | 11/11 |
| NeMo TitaNet Large | 8/11 | 10/11 |
| WeSpeaker ResNet34 | 8/11 | 8/11 |

Режим sherpa-onnx «ровно N говорящих» работал ненадёжно: при N = 3 он выдавал двоих. Поэтому число говорящих
уточняется собственным кодом.

### Способ группировки при заданном N (20 мин)

| Способ | N = 3 |
|---|---|
| иерархическая кластеризация, average linkage | 136/187, выделяет случайный выброс в отдельного «человека» |
| Ward, k-means или слияние по центроидам | 187/187 |

### Итог на синтетике

| Запись | Авто | N = 3 |
|---|---|---|
| диалог 70 с | 11/11 | 11/11 |
| 20 мин, части по 5, 7,5 и 30 мин | 187/187 при любом размере частей | 187/187 |
| 63 мин, две части примерно по 30 мин | 561/561 | |

По словам точность на 20 минутах 95-96 %. Ошибки приходятся на очень короткие реплики, около секунды, у двух
похожих женских синтетических голосов.

### Реальная запись (круглый стол, 50 мин)

| Версия | Найдено голосов |
|---|---|
| первая, порог слияния 0,8 | 22: шесть основных голосов с 95 % речи и 16 обрывков по 1-8 секунд |
| текущая: слияние при сходстве от 0,88 и присоединение голосов, у которых меньше 12 секунд речи | 8 |

Результат устойчив к параметрам: при сходстве 0,85-0,90 и минимуме 8-20 секунд получается 7-8 голосов.
Косинусное сходство голосовых отпечатков в этой записи: у разных людей 0,78-0,80, у одного человека в разных
частях от 0,9, у обрывков 0,5-0,85, то есть это шум. На синтетике у разных голосов сходство не выше 0,76,
у одного голоса 0,92-0,99.

## 3. Скорость и память

### 20 минут записи с тремя говорящими, `scripts/benchmark.py`

| Движок | Устройство | Модель | Время | Быстрее реального | ОЗУ, распознавание | ОЗУ, разделение голосов | Пик MLX |
|---|---|---|---|---|---|---|---|
| MLX | GPU M4 Pro | large-v3 | 132 с | в 9,0 раза | 4,36 ГБ | 1,33 ГБ | 4,49 ГБ |
| MLX | GPU M4 Pro | large-v3-turbo | 126 с | в 9,4 раза | 2,30 ГБ | 1,31 ГБ | 3,02 ГБ |
| faster-whisper | CPU M4 Pro, int8 | large-v3-turbo | 244 с | в 4,9 раза | 3,57 ГБ | 1,34 ГБ | |

На Apple Silicon видеопамять общая с оперативной, поэтому «Пик MLX» уже входит в ОЗУ распознавания.
Замер точной модели на процессоре остановлен досрочно, чтобы не нагружать ноутбук. Для неё в REQUIREMENTS.md
приведена оценка.

### По этапам (20 мин, M4 Pro)

| Этап | Время | Быстрее реального |
|---|---|---|
| Whisper large-v3 на MLX, только распознавание | 110 с | в 11 раз |
| Whisper large-v3-turbo на MLX, только распознавание | 51 с | в 23 раза |
| Разделение по голосам, 4 потока CPU | 144 с | в 8 раз |
| Распознавание и разделение в одном процессе (мешает GIL) | 272 с | в 4,4 раза |
| Разделение в отдельном процессе | 170 с | в 7 раз |

Число потоков для разделения по голосам на 5 минутах записи: 4 потока дают 35,7 с, 8 потоков 25,9 с,
10 потоков 23,9 с. На CoreML вышло 101,7 с, это медленнее процессора.

### 63 минуты

Обработка заняла 8,6 минуты, то есть в 7,4 раза быстрее реального времени. Пик памяти всех процессов не превысил
4,7 ГБ. Распознавание шло тремя частями примерно по 20 минут (121, 128 и 158 с), разделение по голосам двумя частями
примерно по 30 минут (224 и 256 с), параллельно с распознаванием.

## 5. Сбои и восстановление

| Сценарий | Результат |
|---|---|
| Распознавание падает на частях длиннее 3 минут (имитация нехватки памяти) | части делятся 420, 210, 120 и 90 с, текст получается полным |
| Процесс разделения по голосам убит (SIGKILL) | текст сохраняется целиком, пользователь видит предупреждение |
| Сервер падает посреди обработки (SIGSEGV) | стеки попадают в crash.log, после перезапуска задача повторяется с частями вдвое меньше и доделывается |
| Сервер убит, процесс разделения голосов остался без родителя | завершается сам примерно через 2 с |
| При обновлении не удалось доустановить библиотеки | приложение откатывается к прежней версии, изменённых файлов не остаётся |
| Обновление из интерфейса на клоне с GitHub | прошло дважды, с изменением библиотек и без. Перезапуск в том же процессе занимает около 0,1 с |

## 6. Запись звука компьютера

| Проверка | Результат |
|---|---|
| macOS 26: помощник на Core Audio Process Tap, 48 кГц, стерео | звук всех приложений записывается, уровень от -15 до -35 дБ при воспроизведении. Микрофон не участвует |

## 7. Установка

| Где | Как | Результат |
|---|---|---|
| macOS (M4 Pro): чистая копия, пустая домашняя папка, путь с пробелом и кириллицей, без uv | `install.sh --model tiny` | 2 мин 11 с, самопроверка прошла, приложение в «Программах» запускается |

## Как замерить у себя

```bash
.venv/bin/python scripts/benchmark.py путь/к/записи.m4a large-v3        # macOS / Linux
.venv\Scripts\python.exe scripts\benchmark.py путь\к\записи.m4a large-v3   # Windows
```
Скрипт выводит одну строку JSON: устройство, время, во сколько раз это быстрее реального времени, оценку на час
записи и пик памяти. Больше всего не хватает замеров на Windows с NVIDIA и на базовых M1 и M2, для них в требованиях
пока оценки. Если пришлёте строку в Issues, она появится здесь.
