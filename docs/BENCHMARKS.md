## Условия

**Компьютер:** MacBook Pro, Apple M4 Pro (14 ядер CPU: 10 производительных + 4 энергоэффективных; 20 ядер GPU),
48 ГБ общей памяти, macOS 26. Даты замеров: 24–25 сентября 2026. Python 3.12, mlx-whisper 0.4.3, faster-whisper 1.2.1,
sherpa-onnx 1.13.8.

**Тестовые записи** (синтетические, в репозиторий не входят):

| Запись | Описание |
|---|---|
| Диалог 70 с | 11 реплик трёх голосов: два голоса Microsoft Edge TTS (мужской и женский) и голос macOS «Милена»; розовый шум; AAC 64 кбит/с, 48 кГц моно — как у диктофона iPhone |
| 5 / 7 / 20 мин | тот же диалог, повторённый подряд (20 мин = 17 повторов, 187 эталонных реплик) |
| 63 мин | 51 повтор диалога с паузами 0–8 с и 2 минутами тишины посередине; AAC 64 кбит/с (561 реплика) |
| Тишина + ALAC | фраза, 40 с тишины с шумом, фраза; ALAC (режим «без потерь» диктофона) |
| Реальная запись | запись круглого стола, 50 мин, несколько участников, шум зала (содержимое не публикуется) |

**Метрики:**
- **WER** — доля ошибок в словах относительно эталонного текста; перед сравнением убираются пунктуация и регистр, «ё» = «е».
  Часть ошибок — не ошибки по смыслу: Whisper пишет «12%» вместо «двенадцать процентов».
- **Реплики верно** — у скольких эталонных реплик говорящий определён правильно
  (по большинству времени реплики, при лучшем сопоставлении номеров говорящих).

## 1. Точность распознавания

| Модель | Движок | Запись | WER | Время |
|---|---|---|---|---|
| large-v3 | MLX (GPU) | диалог 70 с | **2,4 %** | 17–20 с, включая загрузку модели |
| large-v3-turbo | MLX (GPU) | диалог 70 с | 4,0 % | 13,5 с |
| large-v3-turbo | faster-whisper, CPU int8 | диалог 70 с | 4,0 % | 16 с |
| large-v3 | MLX (GPU) | 63 мин | **2,46 %** | 8,6 мин |

- На 40 секундах тишины Whisper ничего не придумал; фразы вида «Субтитры сделал…» дополнительно отсекаются фильтром.
- Известное ограничение: Whisper изредка пропускает слово на стыке своих 30-секундных окон — ≈4 слова на час записи (0,06 %).

## 2. Разделение по голосам

### Выбор модели голосовых отпечатков (диалог 70 с, sherpa-onnx)

| Модель | Авто (порог 0,5) | Авто (порог 0,6) |
|---|---|---|
| **3D-Speaker ERes2NetV2** (выбрана) | **11/11** | **11/11** |
| NeMo TitaNet Large | 8/11 | 10/11 |
| WeSpeaker ResNet34 | 8/11 | 8/11 |

Режим sherpa-onnx «ровно N говорящих» оказался ненадёжным (при N = 3 выдавал 2), поэтому уточнение числа говорящих
сделано своим кодом.

### Способ группировки при заданном N (20 мин)

| Способ | N = 3 |
|---|---|
| иерархическая, average linkage | 136/187 — выделяет выброс в отдельного «человека» |
| **Ward** / k-means / слияние по центроидам | **187/187** |

### Итог на синтетике

| Запись | Авто | N = 3 |
|---|---|---|
| диалог 70 с | 11/11 | 11/11 |
| 20 мин, части по 5 / 7,5 / 30 мин | 187/187 при любом размере частей | 187/187 |
| 63 мин (две части по ≈30 мин) | **561/561** | — |

Пословная точность на 20 минутах: 95–96 % слов. Ошибки — на очень коротких репликах (≈1 с) двух похожих женских
синтетических голосов.

### Реальная запись (круглый стол, 50 мин)

| Версия | Найдено голосов |
|---|---|
| первая (порог слияния 0,8) | 22: шесть основных голосов ≈95 % речи + 16 «крошек» по 1–8 с |
| **текущая** (слияние при сходстве ≥ 0,88 + присоединение голосов с речью < 12 с) | **8** |

Результат устойчив к параметрам: сходство 0,85–0,90 и минимум 8–20 с дают 7–8 голосов.
Косинусное сходство голосовых отпечатков: разные люди в этой записи — 0,78–0,80, один человек в разных частях — ≥ 0,9,
«крошки» — 0,5–0,85 (шум). На синтетике разные голоса — ≤ 0,76, один голос — 0,92–0,99.

## 3. Скорость и память

### 20 минут записи (3 говорящих), `scripts/benchmark.py`

| Движок | Устройство | Модель | Время | Быстрее реального | ОЗУ: распознавание | ОЗУ: разделение голосов | Пик MLX |
|---|---|---|---|---|---|---|---|
| MLX | GPU M4 Pro | large-v3 | 132 с | ×9,0 | 4,36 ГБ | 1,33 ГБ | 4,49 ГБ |
| MLX | GPU M4 Pro | large-v3-turbo | 126 с | ×9,4 | 2,30 ГБ | 1,31 ГБ | 3,02 ГБ |
| faster-whisper | CPU M4 Pro, int8 | large-v3-turbo | 244 с | ×4,9 | 3,57 ГБ | 1,34 ГБ | — |

На Apple Silicon видеопамять общая: «Пик MLX» входит в ОЗУ распознавания, а не добавляется к нему.
Замер точной модели на процессоре был остановлен досрочно, чтобы не нагружать ноутбук, — для неё в REQUIREMENTS.md дана оценка.

### По этапам (20 мин, M4 Pro)

| Этап | Время | Быстрее реального |
|---|---|---|
| Whisper large-v3, MLX, только распознавание | 110 с | ×11 |
| Whisper large-v3-turbo, MLX, только распознавание | 51 с | ×23 |
| Разделение по голосам, 4 потока CPU | 144 с | ×8 |
| Всё вместе, распознавание и разделение в **одном** процессе (GIL) | 272 с | ×4,4 |
| Всё вместе, разделение в **отдельном** процессе | 170 с | ×7 |

Потоки для разделения по голосам (5 мин записи): 4 потока — 35,7 с; 8 — 25,9 с; 10 — 23,9 с; CoreML — 101,7 с (медленнее CPU).

### 63 минуты

8,6 мин (×7,4); пик памяти всех процессов ≤ 4,7 ГБ; части: распознавание 3 × ≈20 мин (121 / 128 / 158 с),
разделение по голосам 2 × ≈30 мин (224 / 256 с, параллельно).

## 5. Сбои и восстановление

| Сценарий | Результат |
|---|---|
| Распознавание падает на частях > 3 мин (имитация нехватки памяти) | части делятся 420 → 210 → 120 / 90 с, текст полный |
| Процесс разделения по голосам убит (SIGKILL) | текст сохранён целиком + предупреждение |
| Сервер падает посреди обработки (SIGSEGV) | стеки в crash.log; после перезапуска — повтор с частями вдвое меньше, задача доделана |
| Сервер убит — «осиротевший» процесс разделения голосов | завершается сам через ≈2 с |
| Обновление: не удалось доустановить библиотеки | откат к прежней версии, изменённых файлов нет |
| Обновление из интерфейса, клон с GitHub | дважды успешно: без и с изменением библиотек; перезапуск в том же процессе ≈0,1 с |

## Как замерить у себя

```bash
.venv/bin/python scripts/benchmark.py путь/к/записи.m4a large-v3        # macOS / Linux
.venv\Scripts\python.exe scripts\benchmark.py путь\к\записи.m4a large-v3   # Windows
```
Скрипт выводит одну строку JSON: устройство, время, во сколько раз быстрее реального, оценку на час записи, пик памяти.
Особенно нужны замеры на **Windows с NVIDIA** и на **базовых M1/M2** — там в требованиях пока оценки.
Присылайте строку в Issues — она попадёт сюда.
